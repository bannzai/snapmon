# 方向性: snapmon

## 仮説

モンスター収集・対戦ゲームを好むスマホ利用者は、身の回りの物を撮るとその物に似た自分だけのモンスターが生まれ、HP・攻撃・防御・特攻・素早さ・技・PP が勝敗に効くターン制バトルで戦わせられるなら、繰り返し撮って集めて戦う。既存の同種アプリに残る不満 (被写体に似ていない、ステータスが効かない、生成物が変わる・消える) を解消できるかが差になる。

## 必要な機能

- [ ] 撮影・アルバムから選ぶ: カメラで撮るか、端末の写真を選ぶ
- [ ] モンスター生成: 写真の被写体から名前・図鑑の文章 (LLM)、属性・技・HP・攻撃・防御・素早さの基礎値と個体値 (master + Jev)、見た目 (写真から切り出した被写体の画像をそのまま描く。「デザインの方向」) を決める。同じユーザーの同じ被写体は二重に登録しない。生まれた時に決まる部分 (元の写真・名前・図鑑の文章・属性・覚える技の一覧・基礎値・個体値・切り出した絵と装飾のパラメータ・描画の版) は後から変わらず、変わるのはレベルと戦闘中の HP・PP だけ。使える技はレベルに応じて一覧から開放される。属性の相性表は全体で更新され、対戦時点の最新の版を両者に適用する (技の特殊効果も同じ扱い。2026-10-28 の「決めたこと」)
- [ ] 図鑑: 生まれたモンスターを残す。元の写真は並べない (モンスターの絵が元の写真の crop の範囲か写真全体か OS で切り出した被写体で、並べると同じ絵が 2 枚になるため。2026-10-31 の「決めたこと」)
- [ ] 手持ち: 3 体まで選ぶ
- [ ] ターン制バトル (CPU 対戦): 素早さ順に行動し、技の威力・属性の相性・攻撃と防御・PP がダメージと行動に効く。1 戦ごとに、戦闘に出た手持ちのレベルが勝敗に関係なく 1 上がる
- [ ] PvP: 他のユーザーの手持ちと戦う
- [ ] 技のエフェクト
- [ ] アカウントと引き継ぎ: 二重登録の判定と PvP に要るユーザーの識別。機種変更しても図鑑が残る
- [ ] 不適切な画像・人物の扱い: 不適切な写真と人物 (顔) が写る写真からは生成しない。他人に見せる場面 (PvP) ではストアの UGC 要件 (フィルタ・通報・ブロック・連絡先) を満たす
- [ ] 未成年向けの安全策: 対象は 13 歳以上とし、利用規約とストアの年齢区分で表す (アプリ内の年齢の確認は置かない。2026-10-23 の「決めたこと」)、モンスターの名前・図鑑の文章が AI 生成であることの開示 (利用規約・プライバシーポリシー・ストアの説明文で行い、画面には出さない。2026-10-30 の「決めたこと」)、子ども向けのシステムプロンプト、生成した文章とその場で作った定義のコンテンツフィルタ、法令順守 (COPPA 等) の方針のプライバシーポリシーでの表明 (Claude API を未成年が触れる製品で使う条件。対象年齢の決定は「決めたこと」)
- [x] 体験から始める導線: 最初の体験は「写真を選ぶ → 裏でモンスターを作る → 対戦相手を探す → バトル → 生まれたカードと勝敗」で、アカウント (Apple / Google の連携) は後から。Web もアプリも同じ (2026-10-23 の「決めたこと」)
- [ ] 共有: 図鑑のカードとバトルの結果を SNS に出す (目的「バズらせる」の導線)
- [ ] 計測: 生成・バトル・共有のイベントを送る (判定基準の計測元。共有は最初の判定日に判定基準へ足す候補)
- [ ] 法務ドキュメントと紹介ページ: 利用規約・プライバシーポリシー・サポート連絡先

## デザインの方向

`documents/design/mock-2026-10-21/` のモックの方向で進める (見た目と体験の方向の判断 https://github.com/bannzai/snapmon/issues/7 に bannzai がチャットで「そんな感じでやろう」と返答。2026-10-21)。

- 色: 深い紫がかった黒の地 (#15121C)、電気のような黄緑のアクセント 1 色 (#C6F432)、カードは生成りの白 (#F4F1EA)、HP の減りは珊瑚色 (#FF6B6B)
- 文字: 見出し Dela Gothic One、本文 Zen Kaku Gothic New (Google Fonts)
- 角丸は大きめ (12〜24px)、ボタンは四角に近い角丸。錠剤型・グラデーションの帯・絵文字のアイコン・一部だけの斜体は使わない
- 画面の構成: 撮る (ファインダー中心) → 生まれた (カード) → 図鑑 (手持ち + 3 列) → バトル (相手が上・自分が下・技 4 つ) → 対戦相手。下タブは図鑑・撮る・対戦。初回の体験の順は「写真を選ぶ → (裏で生成しながら) 対戦相手を探す → バトル → 生まれたカードと勝敗」(2026-10-23 の「決めたこと」)
- モンスターの絵: 写真から被写体を切り出した画像をそのまま描く。目・口・手足・オーラ・輪郭線などの装飾は重ねず、物に見えてよい (2026-10-29 の「決めたこと」)。切り出しの範囲はクライアントだけで決める: iOS 17 以降は OS の切り出し (写真の長押しで被写体を持ち上げる機能と同じ Vision の前景のマスク)、それが使えない環境 (iOS 16 以前・Android・Web) と被写体を見つけられなかった時は、ユーザーが写真の上で正方形の枠を動かして決める (crop)。サーバーはマスクを作らず、送られたマスクを検査済みの元の写真に適用し、マスクが無ければ写真全体を絵にする。被写体を切り出せない写真もエラーにしない。切り出した絵は PvP と共有カードで他人にも見せる。crop の範囲とマスク無しの絵には背景が写り、元の写真の一部 (写真全体のこともある) が他人に見える (2026-10-22 に「決めたこと」で AI 生成のイラストから変更し、2026-10-28 に切り出しをクライアントだけにした。経路と原価は ADR 0002)

出典: https://github.com/bannzai/snapmon/issues/2#issuecomment-6308773377 。設計への落とし込みは「決めたこと」の agent の行と ADR 0001。

- ポケモンのターン制に近い。技・PP・属性の相性 (弱点) がある
- モンスターは属性を複数持てる。技の属性は 1 つ
- ステータスは HP・攻撃・防御・素早さと、個体ごとの個体値。特性・性格は無い
- レベルがある。1 回戦闘するとレベルが 1 上がり、上限は 999。進化・タマゴは無い
- 手持ちは 3 体まで
- 名前と図鑑の文章は LLM が作る。属性・初期技とレベルで覚える技・ステータスと個体値・同じ被写体の二重登録の判定は、内部の master ファイル (属性・技・エフェクトの定義) と Jev (TypeSafe の判定 API) の組み合わせで決める。登録時に既存の属性・技が合わなければ、その場で新しく作る
- 二重登録の防止はユーザー単位 (同じユーザーが同じ画像・被写体を登録できない。別のユーザー同士で被るのはよい)
- PvP がある
- 技にはエフェクトがある。技の master にエフェクトの対応を持ち、AI 生成か低コストのパーティクルで作る。強い技だけ・技間で共用・後から追加のどれでもよい
- 技と効果は多く用意する (画像の種類が多いため)
